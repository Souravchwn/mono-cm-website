# 08 — Trust Layer

**Visitor should feel:** "They're credible."

## Objective
Prevent the page from feeling like a concept project. **Treat this as a first-class requirement,
not a placeholder section** — a hyper-polished, futuristic site can make skeptical executives
*more* suspicious ("is this real?"), and this section is the direct counterweight to that.

## Copy (exact — sub-sections)
- **Founder / Team** — who's building Mono CM
- **Engineering** — unified data architecture explanation
- **Real Product** — actual screenshots
- **Customer Evidence** — logos, testimonials, pilot projects, case studies, metrics (when available)
- **Security** — data security, authentication, backup, infrastructure, access control

## Governing rule
Every major visual claim on the page should eventually connect to a real artifact:
```
Claim → 3D demonstration → Actual Mono CM UI → Real project example → Measured outcome
```
When building this section, literally trace each major claim made earlier on the page (hero
headline, Section 02 architecture claim, Section 06 outcomes) back to what's shown here — gaps in
that chain are gaps in the page's credibility, not just missing content.

## ⚠️ Data integrity — read before implementing
- The hero's "340+ companies waiting" indicator is governed by this same rule — only publish once
  genuinely true.
- **Customer Evidence** subsection (logos, testimonials, metrics) must not be fabricated or use
  placeholder/stock content presented as real. If real evidence doesn't exist yet, omit the
  subsection or clearly mark it as forthcoming rather than filling it with placeholder-that-looks-real
  content. See `context/data-integrity.md`.
